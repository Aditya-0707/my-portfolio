Overview

Proactive System Intelligence

API Pulse is a web-based monitoring and analytics platform designed to provide real-time visibility into critical API ecosystems across SIT, UAT, and Production environments. It was developed to proactively detect performance bottlenecks, isolate failures, and prevent system-wide downtime in a complex BRMS-driven architecture.

How It Works

Real-Time Monitoring Pipeline

API Pulse follows a continuous monitoring loop that captures, analyzes, and alerts on API performance in real-time.

01

API Data Capture

Google Apps Script captures real-time response data from 9 APIs across SIT, UAT, and Production environments.

02

Log Storage & Retention

API responses, timestamps, and status codes are logged into Google Sheets with 24-hour rolling retention.

03

Performance Analytics

Real-time and 24-hour average response times are computed; load distribution is analyzed per API.

04

BRMS Rule Correlation

API performance is mapped against BRMS rule execution logs to identify parameter conflicts and rule inefficiencies.

05

Dashboard Visualization

Custom frontend renders live graphs, tables, and API-wise performance visualizations for real-time monitoring.

06

Failure Alert & Notification

Automated alerts dispatched via Microsoft Teams and email when downtime or threshold breaches are detected.

The Challenge

Intermittent Failures, Blind Debugging

The client's system heavily depended on a central BRMS API ("Expose") integrated with 8 downstream APIs. Intermittent slowdowns and timeouts in these dependent APIs were causing cascading issues that traditional debugging couldn't isolate due to non-uniform failure patterns.

🛑

System Failures

Complete system failures caused by unidentified downstream bottlenecks in the BRMS architecture.

⏳

Delayed Identification

Lack of real-time visibility meant issues were only identified after users reported them.

🧩

High Debugging Effort

Debugging involved multiple teams sifting through raw logs, wasting hours of engineering bandwidth.

📉

UAT Productivity Loss

Repeated downtime during critical User Acceptance Testing (UAT) phases severely hampered project timelines.

Key Features

Data-Driven Visual Debugging

I designed and developed a real-time monitoring dashboard that transformed raw API logs into actionable insights. By capturing API response data in real-time (via GAS + Google Sheets), the system mapped API responses to BRMS rule execution logs to correlate performance with rule complexity.

01
📊

Live API Dashboard

Visual tracking of all 8 dependent APIs plus the master “Expose” API in a centralized view.

  • Unified view of the API ecosystem
  • Real-time status indicators
  • Load distribution analysis
02
⚡

Performance Analytics

Calculates real-time and 24-hour average response times to benchmark normal operations.

  • Live response time tracking
  • 24-hour historical averages
  • Latency spike detection
03
🔍

Root Cause Detection

Uses visual pattern analysis to identify conflicting parameters and rule-level inefficiencies.

  • Correlation with BRMS execution logs
  • Parameter conflict isolation
  • Inefficient rule highlighting
04
🚨

Instant Failure Alerts

Automated notifications when system downtime or critical latency thresholds are detected.

  • Microsoft Teams webhook integration
  • Automated email alerts
  • Proactive rather than reactive
05
🕒

24-Hour Log Retention

Maintains historical performance tracking specifically optimized for trend analysis and debugging.

  • Trend visualization over time
  • Pattern recognition across shifts
  • Lightweight data storage via Sheets
